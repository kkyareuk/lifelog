- 계정 전환·오래된 응답 배제·첫 로그인 데이터 승계·저장 공간 부족 복원·클라우드 병합·로그 원문 보존 회귀 검사를 통과했습니다.

## 이미지 전체 삭제
설정 → 저장과 동기화 → 내 이미지 전체 삭제. 클라우드 파일 수와 삭제 범위를 보고 확인 후 실행합니다. 로그인 UID는 서버에서 검증하며, 요청 본문의 다른 UID로 삭제할 수 없습니다. 실제 사용자 이미지 삭제는 개발 검증 중 실행하지 않았습니다.

Storage users/{UID}/ 파일, Firestore 개인 동기화 문서와 해당 계정 소유 공유 이미지 링크, 기기 이미지 참조/복원본/IndexedDB를 정리합니다. 캐릭터·관계·우편 본문·구매 내역과 다른 계정 사진은 보존합니다. 다른 계정도 쓰는 동일 기기 이미지 blob은 남깁니다. 다른 이용자가 별도로 복제·다운로드한 파일은 대상이 아닙니다.

imageDeletionState/{UID}가 진행 상태와 epoch를 기록합니다. 삭제 중 이미지·개인 동기화 쓰기를 차단하고, 완료 후 최신 epoch를 가진 쓰기만 허용합니다. 다른 기기도 최신 앱으로 업데이트해야 사진 동기화를 이어갈 수 있습니다. 연결 실패 시 같은 요청 ID로 재시도하며, 실행 중 요청 중복은 잠금으로 차단합니다. 기기 정리가 실패하면 완료로 안내하지 않습니다.

## 후원자 신청을 확인하는 곳
Firebase Console → lifelog-98fff → Firestore Database → 데이터 → supporterRequests → 사용자 UID 문서.

기존 ‘신청 파일 만들기/복사’는 로컬 파일이므로 Firestore에 나타나지 않습니다. 311부터 ‘신청 보내기’를 누르면 접수됩니다. 서버가 구매를 확인하고 꾸미기 권한을 제한합니다. 공개 목록에는 승인된 이름과 꾸미기만 내보냅니다. UID/결제액/거절 사유는 공개하지 않습니다.

운영자가 style.name과 style.visibility를 검토한 뒤 status를 문자열 approved로 바꾸면 공개됩니다. 반려는 status=rejected, reason에 이용자에게 보여줄 이유를 적습니다. 승인 대기는 pending입니다. 앱에서 편집창을 다시 열면 상태가 조회되고, 크레딧 화면은 승인 목록을 조회합니다(공개 응답 캐시 최대60초). 선정적 표현·혐오·욕설·사칭·개인정보 포함 이름은 반려될 수 있다는 안내를 세 언어로 추가했습니다.

신청 파일 만들기와 앱 전송 버튼을 구분해 강조하고, 제공한 나무 원화/미색 상자를 크레딧에 반영했습니다. 우측 메뉴는 투명도 기반 흰 외곽선, 간격12px, 상단96px로 조정했습니다.
