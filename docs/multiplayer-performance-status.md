정적 전체 목록: network-await-inventory.md. 73개의 반복문 내 await 후보와 22개의 이름이 직접 명시된 Firestore 클라이언트 호출. readDocument/readDocuments 별칭은 직접 호출 목록 밖에 있으며 위 표와 반복문 목록에서 별도로 다룸. map 안의 await는 병렬일 수 있고, 타이머·압축·해시는 네트워크가 아니다.

초기 로그인 흐름은 activeSyncDone → 계정 전환 → refreshMediaEpoch → registerSignedInUser → download/readRawCloudGameState이며 이후 refreshGroups가 시작된다. 계정 전환 보호와 이미지 삭제 epoch 확인을 무시하고 전부 병렬화하면 다른 계정 데이터나 삭제된 이미지가 복원될 수 있다. 각 단계의 실기기 소요 시간과 HAR가 아직 없으므로 84초를 3~8초로 줄였다고 주장할 수 없다. Network 완료 시간에는 늦게 시작된 요청과 지속 연결이 포함될 수도 있다.

## 멀티 상태

- 343 배포: 일시적인 그룹 조회 오류에 기존 목록 보존; 재가입 시 남아 있는 기존 역할 유지; group.ownerUid에 해당하는 방장 역할 복원.
- 이번 서버 수정: 본인 소유 집의 외형·이름·배치·서사상 소유 캐릭터 저장 허용. ownerUid는 입력으로 변경 불가. 다른 사람 집은 관리 역할만 수정. 서버의 group.ownerUid를 회원 역할보다 우선.
- 이번 dev 편집기: 방 삭제·벽지·바닥·출입·방 주인·가구 방 이동. 저장 시 deletedRoomKeys 전달.
- 서버 단위 검증: 본인/타인 집, 역할 불일치 방장, 소유 계정 변조, 없는 캐릭터, revision 충돌, 일괄 저장 원자성.
- 아직 미완료: 개인 집의 모든 편집 항목과 멀티의 완전한 동등성, 공유코드로 멀티 집 덮어쓰기, 본인 소유 공용시설·지도 데코의 소유권 모델, 피해 계정의 실제 관리자 복구, 실기기 응답 시간 검증. 사라진 관리자 문서를 클라이언트 캐시만 믿고 승격하지 않음.

새 편집기 문구는 한국어·영어·일본어 모두 작성. 전체 앱의 기존 번역 완성률을 뜻하지 않음.
