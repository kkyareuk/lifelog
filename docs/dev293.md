# 개발판 293 / 1.0.260

## 포함 범위

- 설정 첫 화면에서 미사용 알림 캐릭터 목록, 업적 계산, 테마/표시 선택 화면 생성을 생략한다. 세부 메뉴를 열 때 현재 상태로 계산한다.
- 설정에 크레딧 및 후원자 이름 편집을 추가했다. 앱에 포함된 승인 명단을 읽으며 자동 서버 등록은 하지 않는다. 현재 명단은 비어 있다.
- 색상은 누적 5만원, 모든 꾸미기는 10만원 기준. 그 이후 이름 크기는 최대 36px까지 증가한다. 공개 명단에는 실제 금액과 결제 정보를 포함하지 않는다.
- 사교 활동을 대화·교류, 함께하기, 갈등, 로맨스로 구분하고 행동 선택 전용 대화상자를 추가했다. 캐릭터 상세와 최근 로그는 별도로 유지한다.
- 말다툼, 비아냥, 모욕, 싸움, 차/술, 요리, 공동 게임·공부·독서 등을 추가했다. 갈등 및 요리 장면의 움직임을 연결했다. 주제 입력은 행동을 서술하는 기능이며 임의의 게임 규칙을 만드는 스크립트 기능은 아니다.
- 식사·차·술은 각자 계산/사주기/사달라고 요청하기를 고른다. 요청은 상대의 결제 동의로 서술하지 않는다. 실제 화폐 잔액을 차감하지 않는다.
- 술은 성인/노인 캐릭터만 가능하다. 키스와 사적인 활동은 현재 로맨스 관계에서만 선택 가능하며 기존 접촉 선호 검사를 유지한다.
- 통제적이고 다정하지 않은 성격의 공동 식사/요리에는 간섭, 노인인 경우 경험을 내세운 훈수를 반영한다. 나이의 세부 수치나 모든 성격 조합을 포괄하는 새 시뮬레이션은 아니다.
- 집의 수동 상호작용 쌍을 방 경계 안에 맞추고, 방 편집 종료 시 중간 방 정보 메뉴를 다시 여는 동작을 제거했다. 방 드래그의 겹치는 쌓임 순서를 조정했다.
- Google 로그인 계정의 본인 삭제 버튼을 연결했다. 재인증과 소유 그룹을 포함한 범위 확인 후 기존 서버 삭제 API를 호출한다. 실제 이용자 계정 삭제 테스트는 하지 않았다. 다른 로그인 제공자는 메일 요청을 유지한다.

## 검증

- `qa-social293.mjs`: 360×840 명령 전용 팝업, 4개 분류, 활동 선택, 계산 요청의 양측 인물 참조 일치. 설정 화면 생성 5회 약 0.3–1.9ms (데스크톱 Chrome의 소규모 시험 데이터; 실기기 성능 보증 아님).
- `qa-supporters293.mjs`: 설정 진입, 기기 초안 복원, 빈 공개 명단, HTML 텍스트 처리, 애니메이션 및 정지, 화면 폭 확인.
- `check-supporters-social293.mjs`: 금액 경계, 사용자 입력 금액으로 권한 위조 불가, 명단 비공개 필드 제외, 순환 표시, 사교 분류, 다국어, 계산 대상 및 성격 분기.
- 기존 계정 삭제 서비스 모의 테스트, 선물 및 멀티 생활 회귀 검사 통과.

## 범위 밖 / 후속 검증

- App Store 1.0.215 (16)은 이 Android 개발판과 별개다. 실제 iOS 기기 녹화, 제출 빌드 확인, 신고/차단 흐름 검증 및 Apple 회신은 미완료다.
- 실제 계정 삭제 완료, 실제 구매 확인, 실제 사용자 후원 명단 등재는 수행하지 않았다.
- 서버비 절감률이나 전체 실기기 지연 감소율은 측정하지 않았다.

## 후원 명단 관리

1. 사용자가 설정에서 이름·꾸미기를 선택해 초안을 저장하고 신청 내용을 복사하거나 JSON 파일로 전달한다.
2. 제작자가 별도로 실제 누적 응원액과 취소/환불을 확인한다. JSON의 previewAmount는 증빙이 아니다.
3. 저장소에서 `node scripts/approve-supporter.mjs 신청.json 검증한누적금액 public-entry-id review-supporters.js`를 실행한다.
4. 검토 파일을 읽고 동일인의 기존 ID와 중복, 표시 이름, 공개 동의를 확인한다. 공개를 원하지 않는 신청은 동일 ID로 제거한다. 전액 환불은 기존 항목을 검토 후 명단에서 제거한다.
5. 검토한 entries만 supporter-data.js에 반영하고 새 앱 업데이트로 배포한다. 결제 영수증, 이메일, UID를 명단에 넣지 않는다.
